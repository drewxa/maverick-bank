# Maverick Bank

Общая локальная память для **Claude Code и Codex**: предпочтения, решения и уроки в обычных Markdown-файлах. Поиск возвращает выдержку, путь, строки, версию записи и даты. CLI и локальное MCP-подключение используют один банк.

**Release candidate · 0.1.0.** Целевые системы — Windows, macOS и Ubuntu. Выполненные проверки и ограничения — в [VALIDATION](docs/VALIDATION.md); реальные испытания всех сочетаний ОС и клиентов — отдельное условие выпуска. Публичного адреса репозитория или пакета пока нет.

## Установка

Нужны установленный Claude Code или Codex с выполненным входом, Git в PATH и интернет для зависимостей. Распакуйте полученный ZIP выпуска, откройте терминал в его папке и выполните одну команду.

Windows PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Source . -Clients codex,claude
```

macOS / Ubuntu:

```sh
sh scripts/install.sh --source . --clients codex claude
```

Скрипт устанавливает uv при необходимости, пакет и подключения выбранных клиентов. Можно указать только `codex` или `claude`. Банк по умолчанию — `~/.maverick-bank`; другая папка задаётся через `-Bank "путь"` на Windows или `--bank "путь"` на macOS/Ubuntu. В качестве источника можно передать полученный wheel. История Git остаётся локальной.

Для своего банка во всех следующих CLI-командах используйте тот же `--bank PATH` либо задайте `MAVERICK_BANK_HOME` с этой папкой.

Из исходников, если [uv](https://docs.astral.sh/uv/) уже установлен:

```sh
uv tool install .
maverick-bank init
maverick-bank install --clients codex claude --scope user
maverick-bank doctor
```

Перезапустите клиент и подтвердите его обычные разрешения MCP/доверия проекту, если они появятся. Стартовая инструкция просит агента один раз за сессию прочитать `memory_status` и применять настроенную вами политику записи. Подготовленный конфиг ещё не доказывает рабочее подключение. [Подробнее об интеграциях](docs/INTEGRATIONS.md).

## Первое полезное воспоминание

Отправьте агенту безопасную тестовую просьбу:

> Запомни в Maverick Bank, scope `project:onboarding-demo`: в отчётах о состоянии этого демонстрационного проекта сначала указывать следующее действие. Сохрани как подтверждённое пользователем предпочтение со ссылкой на это сообщение. Покажи ID и revision записи.

Откройте **новую сессию**:

> Найди в Maverick Bank со scope `project:onboarding-demo` предпочтение по отчётам о состоянии. Прочитай найденную запись. Что должно быть в первой строке отчёта? Укажи путь и строки источника и сообщи, повлияла ли память на ответ.

Проверка пройдена, если агент вызвал инструменты, прочитал сохранённую запись и применил правило. Ответ без обращения к банку этого не доказывает. Цель 5–7 минут до первой полезной памяти нужно измерять; это не обещание для любого компьютера и соединения.

## Поиск и обслуживание

Базовый полнотекстовый поиск работает без API-ключей, Docker и загрузки модели. Выбранный scope проекта включает его записи и `global`; другие проекты по умолчанию исключены.

```sh
maverick-bank search "отчёты" --scope project:onboarding-demo
maverick-bank status
maverick-bank audit
```

Для локального семантического поиска из папки исходников:

```sh
uv tool install --force '.[semantic]'
maverick-bank semantic install
```

При первой установке можно использовать `uv tool install '.[semantic]'`. Многоязычная модель по умолчанию — ориентировочно **220 МБ**, плюс зависимости и кеш. Загрузка выполняется явно; поиск сам ничего не скачивает. Если модель недоступна, результат честно обозначает полнотекстовый режим. [Настройки модели](docs/CONFIGURATION.md#local-semantic-search).

Обычный поиск/status выполняет структурную проверку выбранного scope при первом использовании и затем по сроку (по умолчанию раз в семь дней), подсказывая агенту разобрать находки. Это не проверяет истинность и не меняет записи. Можно также попросить:

> Проведи аудит Maverick Bank. Прочитай указанные версии и кандидатов, найди дубли, расхождения по смыслу, scope и времени, недостающие источники и сведения для повторной проверки. Отделяй слова пользователя от предположений. Предложи исправления с источниками; ничего не удаляй, не объединяй и не подтверждай автоматически.

`audit` готовит записи выбранного scope для анализа агентом постранично; истинность он не определяет. Продолжайте через `next_offset`; при изменении `dataset_revision` начните заново. Исправления — новые записи со ссылкой `supersedes`. Счётчики отдельно показывают предложенный текст, обслуженные чтения и заявленное агентом использование. Они не доказывают влияние на модель.

Записи можно редактировать в `notes/`. Поиск обновляет изменённые файлы; `maverick-bank reindex` пересоздаёт индекс. История в `.maverick/history` может содержать старые версии удалённого текста. После прерванной записи `maverick-bank recover` восстанавливает отсутствующие файлы ожидающих операций, сохраняя ручные правки, и повторяет обновление истории/индекса. [Резервное копирование и восстановление](docs/CONFIGURATION.md).

## Приватность и удаление подключения

Приложение не отправляет телеметрию, заметки или запросы в облачный сервис. Клиент агента может передавать полученные выдержки своему облачному провайдеру. Явная установка пакетов/модели использует сеть. Файлы не зашифрованы; храните их в закрытой папке и не записывайте секреты. [Границы защиты](docs/PRIVACY.md).

```sh
maverick-bank uninstall --clients codex claude --scope user
uv tool uninstall maverick-bank
```

Используйте тот же банк и scope, что при установке. Удаляются принадлежащие Maverick Bank настройки подключения; сам банк **никогда не удаляется**. Перезапустите клиентов. Изменённые вручную настройки могут потребовать [разрешения конфликта](docs/TROUBLESHOOTING.md).
